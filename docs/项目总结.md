# GMTools Python（梦江南超级GM工具）项目总结

## 1. 项目定位与目标
本项目是“梦江南超级GM工具”的 **Python 移植版/增强版**，提供两套可并行使用的管理入口：

- **桌面端 GUI（PyQt6）**：面向 GM 日常操作，适合本地/内网使用。
- **Web API（FastAPI）**：对外提供 RESTful 接口与静态管理页面，支持远程调用与权限控制。

二者底层共享同一套 **TCP 游戏服通信客户端**（`network/GMToolsClient`），通过 **MessagePack + 自定义加密** 将“Lua 命令”发送到游戏服务器，并接收响应。

---

## 2. 核心运行形态（双入口）

### 2.1 桌面端入口：`main.py`
- 创建 `QApplication`。
- 初始化 `GMToolsClient`。
- 打开 `ui/LoginWindow` 登录窗口。
- 登录成功后通常进入主窗口（见 `ui/main_window.py` / `ui/discord_main_window.py` 相关实现）。

适用：本地 GM 使用、需要更丰富的交互式 UI。

### 2.2 API 服务入口：`api_main.py`
- 使用 `FastAPI` 启动 REST 服务（`uvicorn.run("api_main:app")`）。
- `lifespan` 生命周期中：
  - 初始化 SQLite 数据库（`database/connection.py`）。
  - 连接游戏服务器（可复用 GUI 共享连接）。
  - 初始化业务 `services/*` 并绑定 `dispatcher`。
  - 必要时执行 GM 登录（独立 API 运行时）。

适用：
- 远程管理（可部署在服务器）。
- 自动化脚本/运维工具通过 HTTP 调用。

### 2.3 GUI 内嵌 API（可选）
`modules/api_manager.py` 提供 `APIManager`：
- 在 **GUI 进程内**用 `QThread` 启动 `uvicorn`。
- 将 `api_main` 的 `shared_client` 指向 GUI 已连接的 `GMToolsClient`，避免重复连接游戏服。

## 3. 仓库目录结构概览（按职责）

- **入口与顶层**
  - `main.py`：桌面端入口
  - `api_main.py`：FastAPI 入口
  - `requirements.txt`：Python 依赖
  - `Config.json`：运行时配置（登录信息、API配置、历史玩家ID等）

- **网络通信与协议层**（对接游戏服）
  - `network/client.py`：TCP 客户端、收发包、解密、回调分发
  - `network/dynamic_header.py`：动态包头计算
  - `utils/encryptor.py`：自定义加密/解密（Base64 + 字符替换映射）

- **GUI 层（PyQt6）**
  - `ui/login_window.py`：登录窗口（Discord 风格、记住密码/自动登录、Config.json 读写）
  - `ui/main_window.py`：主窗口（Tab 模块化）
  - `ui/discord_main_window.py`：更复杂的 Discord 风格主窗口（若启用）
  - 其他：`ui/about_window.py`、`ui/server_settings_dialog.py`、`ui/api_service_page.py`、`ui/discord_messagebox.py`

- **GUI 模块层（modules/）**：每个模块负责 UI + 发送命令
  - `modules/base_module.py`：模块基类（Lua 命令拼接、发送）
  - 典型模块：
    - `modules/account_recharge_module.py`（账号+充值综合）
    - `modules/game_module.py`（游戏管理）
    - `modules/character_module.py`（角色管理）
    - `modules/pet_module.py`（宝宝/宠物）
    - `modules/gift_module.py`（物品赠送）
    - `modules/equipment_module.py`（装备定制）

- **API 路由层（routes/）**：HTTP 端点
  - `routes/user_routes.py`：注册/登录/用户管理/审计日志
  - `routes/permission_routes.py`：权限配置（Level → 权限列表）
  - `routes/level_config_routes.py`：等级配置（包含 max_bind_ids 等）
  - `routes/message_routes.py`：站内消息
  - `routes/activity_routes.py`：活动系统（转盘/奖池等）
  - `routes/item_gift_routes.py`：道具赠送系统（配置+等级限制+发放日志）

- **API 业务层（services/）**：对游戏服命令的业务封装
  - `services/base_service.py`：异步 `send_command` + Lua table 构建
  - `services/account_service.py`：账号/充值相关
  - `services/pet_service.py`、`services/equipment_service.py`、`services/gift_service.py`、`services/character_service.py`、`services/game_service.py`
  - `services/item_gift_service.py`：道具赠送系统（更偏业务规则与DB）

- **认证与权限（auth/）**
  - `auth/__init__.py`：JWT + bcrypt（`AuthUtils`）
  - `auth/dependencies.py`：FastAPI 依赖（Bearer 解析、当前用户、管理员/超管）
  - `auth/permission_checker.py`：按 LevelPermission 判断权限
  - `auth/level_permissions.py`：`require_level(min_level)` 依赖工厂

- **数据层（database/）**
  - `database/connection.py`：SQLite 连接与建表
  - `database/models.py`：`User`、`AuditLog`、`Message` 等模型与 CRUD
  - `database/permissions.py`：`Permission`、`LevelPermission`
  - `database/activation_code.py`：激活码（提升用户 level）
  - `database/level_config.py`：等级配置（与用户绑定数量等策略相关）
  - `database/activity_models.py`、`database/item_gift.py` 等

- **静态资源与前端**
  - `static/`：API 附带的静态页面（`/user-management`、`/level-permissions` 等）
  - `frontend/`：Vue 3 + Vite 前端工程（存在 `node_modules`，偏重前端开发形态）

- **脚本与工具**
  - `migrate_db.py`、`migrate_password_plain.py`、`list_users.py` 等
  - `scripts/`：各类辅助脚本
  - `test/`：测试相关

## 4. 核心数据流与调用链

## 4.1 GUI 链路（PyQt6）
1. `main.py` 启动 `QApplication` 并创建 `GMToolsClient`。
2. `LoginWindow` 负责：
   - 读取 `Config.json`（`ConfigManager`）填充账号、记住密码、自动登录等。
   - 执行与游戏服的登录交互（通常使用 `seq_no=1` 登录）。
3. 登录成功后主窗口（`MainWindow`）加载模块：
   - 每个模块继承 `modules/base_module.py::BaseModule`。
   - 模块 UI 点击 → 调用 `send_command(seq_no, command, data)`。
4. `GMToolsClient` 负责：
   - `send(...)` 发送 Lua 命令。
   - 接收线程解包 msgpack、解密、解析 `seq_no/content` 后回调 `on_receive`。
5. `MainWindow.handle_global_receive` 或各模块的回调处理响应显示。

## 4.2 API 链路（FastAPI）
1. `api_main.py` 创建 `FastAPI(app)` 并 include 多个 `routes/*`。
2. API 认证：
   - `Authorization: Bearer <jwt>`
   - `auth/dependencies.py` 验证 token → 加载 `database.models.User`
3. 游戏服操作统一接口（典型）：
   - `/api/account`、`/api/pet`、`/api/equipment`、`/api/gift`、`/api/character`、`/api/game`
   - Body: `{ "function": "xxx", "args": { ... } }`
4. 权限控制：
   - `check_function_permission(user, module, function)` → 使用 `FUNCTION_PERMISSIONS` 映射到权限 code。
   - `auth/permission_checker.py::has_permission` 依据 role 与 level 权限判断。
5. 业务执行：
   - `handle_service_request(service, request)` 反射调用 service 方法。
   - `services/base_service.py` 通过 `asyncio.to_thread` 调用 `client.send(...)` 并使用 `dispatcher` 收集响应。
6. 审计：
   - `database.models.AuditLog.create(...)` 记录用户操作、IP、资源等。

## 5. 游戏服通信协议（关键）

## 5.1 序列化与包结构
- 传输：TCP
- 数据编码：MessagePack（`msgpack`）
- 数据包：
  - 4字节包头（动态计算）
  - 后续为 msgpack 序列化的数据

## 5.2 动态包头
`network/dynamic_header.py::calculate_packet_header(msgpack_length)`：
- 根据 msgpack 数据长度生成 4 字节 header。
- 逻辑包含“长度>512 的进位机制”。

## 5.3 自定义加密
`utils/encryptor.py::GMToolsEncryptor`：
- 加密流程：
  1. GBK 编码 → Base64
  2. Base64 字符按 `_ENCRYPT_MAP` 替换成三字符片段（带逗号）
- 解密流程：
  1. 反向替换 `_DECRYPT_MAP`
  2. Base64 decode（补齐 padding）→ GBK decode

## 5.4 Lua 命令载荷格式
项目大量将业务参数封装为 Lua table 字符串，例如：
- `do local ret={ ["文本"]="命令名", ["玩家id"]="12345", ["数额"]=100 } return ret end`

- GUI 的 `BaseModule` 与 API 的 `BaseService` 均提供 `_build_lua_command()`/`_dict_to_lua_table()`。
- 特殊字段：对 key 为 `"修改数据"` 且 value 已是 Lua 表字符串的情况会“原样拼接”。

## 6. 配置系统

## 6.1 静态配置：`config/settings.py`
包含默认：
- 游戏服地址：`SERVER_HOST`、`SERVER_PORT`
- 默认 GM 账号：`GM_ACCOUNT`、`GM_PASSWORD`
- 协议分隔符：`SEPARATOR`
- `AUTH_TOKEN`（存在但未必处处使用）

## 6.2 运行时配置：`Config.json` + `config/config_manager.py`
`ConfigManager` 提供单例管理与深度合并默认值。
常见字段：
- `Login.Account` / `Login.Password` / `RememberPassword` / `AutoLogin` / `LastLogin`
- `Server.Host` / `Server.Port`
- `PlayerHistory`（最近使用的玩家ID）
- API 配置：`api_host`、`api_port`、`api_auto_start`、`api_known_hosts`、`api_token`

注意：`LoginWindow.SecurityManager` 对保存密码使用了 **固定 salt 的 sha256**，与 API 用户系统（bcrypt）是两套不同体系。

## 7. 认证、权限与等级体系（API）

## 7.1 用户系统（JWT + bcrypt）
- `auth/__init__.py` 提供：
  - `hash_password` / `verify_password`
  - `create_access_token` / `verify_token`
- `auth/user_service.py` 提供：
  - `register` / `login` / `change_password` / `reset_password`

## 7.2 角色与等级
- `User.role`：`user | admin | super_admin`
- `User.level`：1-10（同时 `level_config_routes.py` 支持更大范围的配置，但权限依赖主要以 1-10 为核心）

### 权限判断逻辑
`auth/permission_checker.py::has_permission`：
- `super_admin` 永远允许。
- `level >= 10` 永远允许。
- 否则按 `LevelPermission.has_permission(level, code)` 判断。

### LevelPermission 支持通配符
- `"*"`：全权限
- `"category.*"`：某类下全权限

## 7.3 功能权限映射（关键设计）
`api_main.py` 中 `FUNCTION_PERMISSIONS` 将 **模块方法名** 映射为权限 code。
- `/api/<module>` 请求时，会执行 `check_function_permission(current_user, module, request_data.function)`。

这实现了：
- API 接口不需要为每个方法单独写一个 endpoint。
- 权限粒度仍可到“方法级别”。

## 10. 关键实现细节与工程特征

## 10.1 API 侧响应收集机制（多包兼容）
`services/base_service.py::send_command()`：
- 生成 `request_id` 并在 `dispatcher` 注册 collector。
- `asyncio.to_thread(self.client.send, ...)` 将阻塞发送放入线程池。
- 等待第一个响应事件（timeout 默认 3s），收到后额外 sleep 0.1s 用于收集“可能的后续分包”。
- 返回收集到的所有响应 list（或 dict 状态）。

## 10.2 GUI 侧模块化
`ui/main_window.py`：
- 用 `QTabWidget` 组织模块。
- 通过 `_setup_module()` 先 `module.setup_ui()` 再 `addTab()`。
- `set_account()` 会把当前登录账号注入到各模块 `_current_account`。

## 10.3 业务“命令号 seq_no”设计
项目中常见：
- `seq_no=1`：登录
- `seq_no=2`：充值/一些通用操作
- `seq_no=3`：账号管理类（封禁/解封/改密/称谓等）
- `seq_no=6`：游戏管理类（公告/广播/倍率/活动等）
- `seq_no=7`：登录成功/提示类回包（项目内被当作重要提示显示）

（具体以游戏服协议为准；代码中多处体现此约定。）

## 11. 主要风险点与改进建议（面向生产）

### 11.1 安全配置与密钥
- `auth/__init__.py` 的 `SECRET_KEY` 为硬编码示例值，**生产必须替换**。
- `config/settings.py` 的 `AUTH_TOKEN` 同样是明文常量。
- `Config.json` 存在 `api_token` 字段，建议统一 token/secret 的来源与优先级。

### 11.2 明文密码/弱加密存储
- 数据库 `users.password_plain` 字段存在且会被写入（`UserAuthService.register`）。
- GUI 侧 `SecurityManager` 用固定 salt 的 sha256 保存“记住密码”，安全性有限。

建议：
- 严禁存储明文密码（删除/停用 `password_plain` 写入）。
- GUI 记住密码改为操作系统凭据管理器或加密存储。

### 11.3 CORS 全开
`api_main.py` 设置：`allow_origins=["*"]`，生产建议收敛到可信域名。

### 11.4 日志与调试输出
`network/client.py` 内有大量 `print([DEBUG]...)`，生产环境建议统一使用 `logging` 并加可配置的 log level。

### 11.5 代码质量小问题（可逐步清理）
- `modules/base_module.py` 中出现重复定义与疑似误粘贴的代码段（重复 `show_message` 定义、以及不完整的 data 处理片段）。
- API 路由 include 有重复（`activity_routes` 在 `api_main.py` 中 include 两次）。

这些不一定立刻致命，但会增加维护成本。

## 12. 扩展点（如何新增功能）

### 12.1 新增一个“游戏服命令”（API）
- 在对应 `services/<xxx>_service.py` 添加一个方法（建议 async，返回响应数据）。
- 在 `api_main.py::FUNCTION_PERMISSIONS` 增加 `module -> function -> permission_code` 映射。
- 前端/调用方按统一格式请求 `/api/<module>`。

### 12.2 新增一个 GUI 功能模块
- 在 `modules/` 新建模块类继承 `BaseModule`，实现 `init_ui()`。
- 在 `ui/main_window.py::create_module_tabs()` 里添加 Tab。

### 12.3 新增一套“非游戏服”的业务系统（例如道具赠送）
当前项目已提供范例：`routes/item_gift_routes.py + database/item_gift.py + services/item_gift_service.py`。
可以按此分层模式继续扩展。

## 14. 一句话总结
这是一个以“**TCP + msgpack + 自定义加密**”对接游戏服、上层同时提供 **PyQt6 GUI** 与 **FastAPI REST** 的 GM 管理工具；API 侧引入了较完整的 **用户/权限/等级/审计/激活码/消息/活动/道具系统**，具备进一步产品化与多租户权限控制的基础。
